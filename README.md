# P0 — 파일 상태 조사 도구

맥용 파일 정리 도구 시리즈(1~3편)를 만들기 전에,
**무엇을 먼저 만들지 결정하기 위한 실측 도구**입니다.

`p0_survey.py` 는 터미널에서 도는 조사 도구입니다.
이걸 **py2app 으로 `.app` 으로 포장**해서 동료 9명에게 배포하려고 합니다.

## 이 도구가 답하는 것

```
① 2편 먼저냐 3편 먼저냐          ← 가장 중요
② 3편이 남들과 다른가 (계보)
③ 2편의 범위 (홈 전체 vs 세 폴더)
④ 비어도비 사용자를 받을 수 있나 (썸네일)
⑤ 로컬 LLM 이 필요한가
⑥ 3D 대응의 시작점
⑦ 제품 첫 스캔이 몇 분짜리인가   ← 조사 중에 알게 된 것
```

---

## 실측에서 배운 것 (반드시 알고 시작하세요)

### ① 첫 스캔은 몇 시간일 수 있습니다

```
1차  3시간 12분
2차       31분
4차        3분
```

**백신 때문입니다.** 파일을 처음 열 때 전체를 검사합니다.
8GB 파일에서 768KB 읽는 데 18분이 걸렸고, 두 번째는 0ms 였습니다.

→ **한 번 읽은 것은 저장해 두고 다시 읽지 않습니다** (`ReadCache`)
→ 화면은 **예상 시간 고지 → 진행 표시 → 중단·재개** 여야 합니다

### ② macOS 는 한글 파일명을 자모로 쪼개서 저장합니다 (NFD)

`스크린샷` 이 디스크에는 `ㅅ+ㅡ+ㅋ+ㅡ+ㄹ+ㅣ+ㄴ+ㅅ+ㅑ+ㅅ` 으로 들어 있습니다.
정규식을 합쳐진 형태(NFC)로 쓰면 안 맞습니다.

이것 때문에:
- 스크린샷 265장이 한 가족으로 묶여 회수량이 3.1GB 부풀려짐
- 한글 이름 비율이 **0.4% 로 세어짐** (실제 6%)

→ **파일 이름을 읽는 순간 NFC 로 바꿉니다.** `lang_ko.normalize_text()`
→ 영어만 쓰는 환경에서는 절대 안 터지는 버그라 놓치기 쉽습니다

### ③ 원인을 짐작하지 말고 재세요

느린 원인을 다섯 번 짐작해서 다섯 번 틀렸습니다
(iCloud · 디스크 성능 · 다른 작업 경합 · 백신 · 클라우드 자리표시자).

→ `StepLog` 가 단계별 시간을 **항상** 기록합니다. 옵션이 아닙니다
→ 느리면 `p0_steps.log` 를 보고 그 지점만 고칩니다

## 지켜야 할 원칙

| | |
|---|---|
| **읽기 전용** | 파일을 지우거나 옮기지 않습니다. 쓰는 것은 결과 파일뿐 |
| **실패를 숨기지 않기** | `except: pass` 금지. 못 읽었으면 세서 보고합니다 |
| **언어는 사전으로** | 엔진(`p0_survey.py`)은 언어를 모릅니다. 낱말은 `lang_ko.py` 에 |
| **자가진단** | `--selftest` 가 통과해야 최신 파일입니다 |
| **공유 모드** | `--share` 면 파일 이름이 결과에 안 들어갑니다 |

---

## 기준선

`baseline.txt` 는 개발자 본인 맥(58,223개 · 148GB)에서 잰 결과입니다.
**`--share` 로 만들어 파일 이름이 들어 있지 않습니다.**

> ⚠ `p0_report.txt` 와 `p0_testset.md` 에는 실제 파일 이름이 들어갑니다.
> `.gitignore` 로 막아 뒀습니다. 풀지 마세요.
